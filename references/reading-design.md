# 根据内容选择样式

先问：读者要顺着理解、快速定位、按步骤操作，还是比较几个对象？据此选择表达方式。下列候选按信息关系选择，不是每篇必须使用的样式清单；平台能力、用户要求、体裁和已有模板共同决定最终形式。

## 组织内容

| 阅读需要 | 可以考虑 | 判断要点 |
|---|---|---|
| 建立主题层次与导航 | 标题、子标题、目录、章节编号 | 层级体现内容关系；不要为了字号乱选层级。既有编号、目录和引用需要保留时，不擅自改号或把静态编号误称为自动编号。 |
| 解释一个连续的意思 | 段落、短导语、小节 | 因果、推理和叙述保持连贯；段落太密时按意思拆分，不把每句变成标题。 |
| 按先后完成操作 | 有序列表 | 顺序与依赖关系确实重要时才编号，保留条件、异常和说明。 |
| 并列查看要点或术语 | 无序列表、术语表、短段落 | 项目处于同一层级；长解释仍可用段落，不为列表而拆散内容。 |
| 标识真正可执行的任务 | 待办列表 | 只用于可以勾选的任务或检查项，不把普通陈述伪装成待办。 |
| 对比多个对象 | 表格、短分栏、并列列表 | 先确认有共同比较维度；长文字、复杂关系或窄屏不适合时改用连续段落。 |
| 划分独立主题 | 留白、分隔线 | 根据实际节奏判断，不在每段或每个标题旁机械加线。 |
| 次要但有用的补充 | 注释、脚注、折叠块 | 不把理解正文所必需的内容藏起来；保留来源与上下文。 |

## 突出与引用

- **粗体**适合读者需要快速定位的关键结论、条件或少量术语。避免整段全粗，或每一行都加粗开头。
- **斜体**适合轻量区分、术语或作品名；跟随文种和既有约定。重要限制不能只靠斜体暗示。
- **下划线、删除线、上标和下标**按语义使用：下划线注意与链接区分，删除线表示删除或变更，上下标保留准确含义。
- **行内高亮、文字色和底色**突出少量确有必要的短词句，不把整段染色，也不靠颜色单独表达风险或状态。
- **提示块、高亮块、警告块**适合需要单独注意的定义、前提、推荐、限制或风险；每个块应帮助阅读，不为装饰给每节加框。平台、用户或体裁不适合时用清楚的普通段落。
- **引用块**用于真实引文或明确归属的原话，保留来源和原意；不要把作者自己的结论伪装为引文，也不把普通强调都做成引用。

颜色可作辅助：没有其他明确约定时，蓝色表示说明，绿色表示推荐或已确认，黄色表示注意或待确认，红色表示风险，灰色表示中性补充。颜色有清晰语义即可，不要求用齐，也要保证不同显示模式下可读。

## 内容对象

- **代码、命令和配置**：短标识用行内代码，较长内容用代码块；保留字符、缩进和语言标记。
- **图片、图表、示意图**：只在帮助理解时使用；保留图片及其图注、标记、来源和与正文的对应关系。
- **公式和符号**：保留变量、上下标、单位和编号；目标不支持时选能保留原意的方式并说明。
- **链接、引用和脚注**：让读者可以找到出处；原有链接、锚点和资源不能为美化而丢失。
- **折叠、标签页等交互组件**：只有目标环境实际支持且确有阅读价值时使用；关键内容不能因交互而难以发现。

## 交付前判断

检查核心定义、结论、前提、限制和操作风险是否清楚；步骤、并列要点、术语、引文和比较是否各有合适形式；是否存在碎标题、文字墙或过度强调。对适合与不适合的内容给出具体判断，不按样式数量评判文档。

已有文档只在授权范围内调整，尽量保留原文、顺序、链接、图片、公式、表格、评论和手工排版；无法证明保真时保留并说明。回读修改结果；没有实际验证的渲染、链接或交互效果不得声称已验证。
